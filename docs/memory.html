Memory Layout

Every bus target is selected by a single top-byte compare (addr[31:24]), so the address space is really just 256 possible 16 MB windows - only three are wired up. Nothing below that top byte is range-checked against the region's real size, so a region smaller than its window mirrors throughout the rest of it (see the SRAM note below).

Address Map

addr[31:24], tinymcu_addr_decoder.vhd

256 possible top-byte values, 3 actually decoded. Every unlabeled segment reads back as 0 and acks immediately - there is no bus fault, no stall.

Boot ROM / Flash

rtl/core/tinymcu_imem.vhd
0x0000_0000-0x0000_7FFF 32 KB real

Boot ROM. tinymcu_imem_bootrom.vhd, sized by IMEM_ADDR_WIDTH (default 13 → 213 words). Synchronous read, BRAM-inferable - one cycle of latency on both the fetch and data-side port (see the pipeline doc's IF stage). Holds whatever scripts/hex2rom.py last wrote into it.

0x0000_8000-0x00FF_FFFF ≈ 16 MB − 32 KB reserved

Flash + XIP. Reserved in tinymcu_pkg.vhd (FLASH_BASE/FLASH_END) and in sw/linker.ld's FLASH output region, but tinymcu_imem.vhd only ever instantiates the Boot ROM - reads up here currently return 0.

SRAM

rtl/core/tinymcu_sram.vhd, tinymcu_sram_generic.vhd
0x0200_0000-0x0200_0FFF 4 KB physical real

RAM_ADDR_WIDTH default 10 → 210 words, word-addressed (addr_i = req_i.addr(ADDR_WIDTH+1 downto 2)). Synchronous read, same BRAM-style one-cycle latency as the Boot ROM.

Aliasing

tinymcu_sram_generic.vhd only ever looks at the low ADDR_WIDTH address bits - nothing above that is checked. The 4 KB array therefore repeats every 4 KB across the entire 16 MB 0x0200_0000 window; e.g. 0x0200_1000 aliases 0x0200_0000.

Linked vs. physical

sw/linker.ld only carves out 1 KB for its RAM output section (_stack_top sits at 0x0200_0400), well short of the full 4 KB the hardware actually provides - headroom, not a hardware limit.

Peripherals

rtl/peripherals/tinymcu_periph.vhd, addr[31:8]

Same top-byte-style trick one level down: each peripheral gets a fixed 256 B window, selected by addr[31:8]. Registers below are word-aligned offsets inside that window; matches sw/lib/tinymcu_*.h exactly.

Unmapped peripheral space

0x0400_0300-0x04FF_FFFF is not decoded by tinymcu_periph.vhd - reads as 0, same as any other unmapped address. Room for future peripherals without touching the top-level decoder.
