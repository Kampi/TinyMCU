GPIO

One 32-bit port, one bit per pin in every register. Output drive is strong, pull resistors are weak ('H'/'L'), and every pin can raise its own edge-triggered interrupt, gated by both a per-pin enable and one master switch.

Pin Driver

gen_pins, one instance per bit of gpio_port

Each pin is one concurrent conditional assignment, driving exactly one of four outcomes onto the inout pad:

DDR(i) = 1 OUT(i) Strong drive, output mode. Overrides any pull on the same pin (and any weaker external signal).
PULL_EN(i)=1, PULL_SEL(i)=1 'H' Weak pull-up. A real external driver on the same pin wins, since this is genuinely weak, not a second strong driver.
PULL_EN(i)=1, PULL_SEL(i)=0 'L' Weak pull-down. Same weak-vs-strong resolution as pull-up.
otherwise 'Z' Floating input, no pull. Left entirely to whatever (if anything) is externally driving the pad.

Reading a floating, undriven pin back through IN or through the interrupt logic's own sampling both go through to_x01: 'H'/'L' normalize to a clean '1'/'0', but a genuinely undriven 'Z' normalizes to 'X', which never equals '1' in any of the comparisons below, so a floating pin can never spuriously report an edge or a level on its own.

Debounce

CONFIG bits 15:1, applies to the whole port at once

A per-pin counter (debounce_cnt) counts consecutive cycles the raw pad disagrees with that pin's current gpio_debounced value. The value only updates once the counter reaches the threshold in CONFIG bits 15:1; any disagreement shorter than that gets reset back to zero the moment the raw level agrees again, rejecting the glitch entirely.

cycle (threshold=3)c0c1c2c3c4
raw pad11111
debounce_cnt01230
gpio_debounced00001

The counter has to reach the threshold, which takes one more cycle than the threshold itself: four disagreeing samples (c0-c3) before gpio_debounced flips, visible at c4. A glitch that reverts before the counter gets there resets it to zero immediately, with gpio_debounced never moving at all.

Threshold 0 (the reset default) bypasses the filter entirely: gpio_filtered falls straight through to the raw, zero-latency pad reading, and interrupt behavior is identical to before this feature existed. The filter only ever affects the interrupt-detection path below, never the IN register: a plain digital read stays immediate.

Interrupts

any-edge, per-pin + global gating, sticky status

Every cycle, gpio_port_prev samples gpio_filtered unconditionally (the debounced value when the filter's active, the raw pad otherwise, see Debounce above). A pin's current value XOR'd against that one-cycle-old sample is '1' for exactly one cycle right after a real transition; that's the only source of "did this pin just change".

cyclec0c1c2
gpio_filtered(i)111
gpio_port_prev(i)011
edge (xor)100
INT_STATUS(i)011

The pin actually changes during c0; the edge is detected (and, if enabled, latched into INT_STATUS) one clock edge later, at the start of c1, then holds through c2 and beyond until software clears it, since the process only ever sets a bit on a true edge and otherwise leaves it exactly as it was.

A bit only reaches INT_STATUS when three things are all true the cycle the edge is seen: the per-pin INT_CONFIG(i) bit, the global CONFIG bit 0, and the edge itself. irq_o is simply "INT_STATUS is nonzero", a single OR-reduction, so it stays high for as long as any pin's flag is still set.

Notes

INT_STATUS needs a read-modify-write to clear selectively

The hardware doesn't implement write-1-to-clear: whatever bit pattern gets written becomes the register's new content, full stop. Clearing exactly one pin's flag while leaving others set means read-AND-write from software, not a plain store, exactly what tinymcu_gpio_irq_clear() does.

CONFIG is otherwise general-purpose

Only bits 15:0 have a defined meaning (bit 0, bits 15:1). The driver only ever touches those bits with |=/&= or a mask, never a plain assignment, so it doesn't clobber whatever else software might be storing in bits 31:16.

Both enables gate every pin the same way

There's no way to leave the global switch off for some pins and on for others: CONFIG bit 0 is a single master enable across the whole port, on top of each pin's own INT_CONFIG bit.

One cycle of detection latency

Every edge costs exactly one clock cycle between the physical transition and INT_STATUS updating, see the Interrupts timing table above. irq_o itself is purely combinational from INT_STATUS, so it tracks that same one-cycle latency, nothing more.
